# Аудит безопасности

Проверялся распакованный оригинал (`app.asar`) и переписанный исходник.
Ниже — что код реально делает, куда ходит по сети и какие риски остаются.

## Краткий вывод

Вредоносного поведения не найдено: нет `eval`/`new Function`/`vm`, нет
скрытых payload'ов, string-array или сетевых «маячков». Код не читает пароли
Steam, не трогает кошельки/куки/буфер обмена без действия пользователя и не
прописывается в автозагрузку. Все записи — в `%APPDATA%`, выбранную папку игры
и временную папку обновления.

## Сетевые адреса

| Адрес | Назначение |
| --- | --- |
| `huggingface.co` (датасеты из `config.json`) | манифест и файлы игры, установщик лаунчера |
| `hf.co` | сокращённые ссылки Hugging Face |
| `api.gamemonitoring.ru` | онлайн серверов, если A2S недоступен |
| `5.42.211.95:35001/35011` | прямые A2S-запросы к серверам игры |
| `steamcommunity.com/profiles/<id>/?xml=1` | публичное имя и аватар Steam |
| `cp.cloudflare.com`, `ya.ru` | проверка наличия интернета |
| `cloudflare-dns.com`, `dns.google` | DoH (включается пользователем/диагностикой) |
| `aka.ms/vs/17/release/vc_redist.x64.exe` | ссылка на VC++ по кнопке «Скачать» |
| `t.me`, `discord.gg`, `woohrust.gamestores.app` | ссылки поддержки/магазина |
| `fonts.googleapis.com`, `fonts.gstatic.com` | шрифты интерфейса |

Других исходящих запросов нет. Телеметрии нет: отчёты создаются локально и
отправляются только вручную (кнопка «Отправить в поддержку» копирует текст в
буфер и открывает Telegram/Discord).

## Работа с Steam

- читается `HKCU\Software\Valve\Steam\ActiveProcess` (PID, ActiveUser);
- читается `config/loginusers.vdf` (имена, SteamID, MostRecent — **не пароли**);
- запрашивается публичный XML-профиль;
- `steamworks.js` получает Web API ticket для App ID из `config.json`.

Тикет кэшируется в памяти на 45 секунд и **никуда не отправляется** — в этом
коде нет сетевого вызова с ним. Это задел на будущую серверную авторизацию.

## Файловая система

| Что | Куда |
| --- | --- |
| Лог | `%APPDATA%/wooh-launcher/logs/launcher.log` |
| Отчёты | `%APPDATA%/wooh-launcher/reports/*.json` (макс. 60) |
| Кэш манифеста/проверок | `%APPDATA%/wooh-launcher/manifests/` |
| Настройки сети | `%APPDATA%/wooh-launcher/network.json` |
| Установщик обновления | `%APPDATA%/WoohProject/launcher-update/` |
| Игра | выбранная пользователем папка |
| Ярлык | рабочий стол, только в собранном приложении |

Дополнительно:

- `taskkill` завершает `RustClient.exe`/`UnityCrashHandler64.exe` только после
  подтверждения пользователя (диалог «Закрыть игру?»);
- zapret: в `lists/list-exclude*.txt` **дописываются** три домена, и только
  после согласия. Другие файлы не изменяются;
- реестр только читается (Steam, VC++, Smart App Control), запись — только
  `shell.writeShortcutLink` для ярлыка;
- автозагрузки нет.

## Проверка загрузок

- манифест игры и файлы идут по HTTPS;
- каждый файл сверяется по SHA-256 из манифеста (полная проверка — после
  скачивания и при глубокой проверке);
- установщик лаунчера проверяется по размеру и SHA-256, затем запускается
  с `/S --force-run`;
- **добавлено:** `resolveInstallPath()` запрещает `..` и абсолютные пути в
  манифесте, чтобы стороннее зеркало не могло записать файл вне папки игры.

## Очистка отчётов

`bug-report.js` заменяет домашний каталог на `%USERPROFILE%`, а все URL
(включая `huggingface.co`, `hf.co`, `datasets/...`) — на `[сервер]`. В отчёт
попадают версия Electron/Windows, ошибка, контекст и хвост лога; пароли и
токены туда не пишутся.

## Остаточные риски

1. **Нет подписи кода.** Ни оригинальный `WoohProject Launcher.exe`, ни
   собранный установщик не подписаны (`NotSigned`). Windows SmartScreen может
   показывать предупреждение; для релиза нужен сертификат и
   `win.certificateFile`/`signingHashAlgorithms` в electron-builder.
2. **Доверие к зеркалам.** Манифест и файлы игры приходят с Hugging Face
   датасетов, перечисленных в `config.json`. Компрометация аккаунта/датасета
   означает подмену игры и (для самообновления) установщика. Подпись манифеста
   или закреплённый хэш это исправили бы, но требуют серверной инфраструктуры.
3. **Запуск скачанного кода.** Лаунчер по назначению запускает
   `RustClient.exe` и установщик обновления. Это ожидаемая функциональность,
   но она делает цепочку поставки критичной.
4. **Smart App Control / антивирус.** Код обходит только ложные срабатывания
   (объясняет пользователю, что делать), а не защиту Windows. Повышение прав
   выполняется через `cmd /c start` и UAC — только для запуска игры.
5. **Steam-тикет.** Сейчас не используется; если его начнут отправлять на
   сервер, это надо делать только по HTTPS и с явным согласием.

## Что улучшено в переписанном исходнике

- `contextIsolation: true`, `nodeIntegration: false`, узкий preload API;
- CSP: `script-src 'self'`, без `unsafe-eval`, внешние скрипты запрещены;
- внешние ссылки открываются в браузере, навигация внутри окна блокируется;
- запрет path traversal в манифестах;
- отчёты и логи очищаются от путей/URL;
- pinned-версии Electron 35.7.5 и `steamworks.js` 0.4.0.
